# Known limitations and integration checklist

## Platform limitations

| Limitation                                                                                              | Consequence                                                                                                                                                                                     | Status                                                                                                                           |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| FunPay has **no public API**.                                                                           | Every FunPay integration relies on markup and endpoints documented by independent open-source clients (Wingman, FunPayAPI). None has been verified by FunPro maintainers against the live site. | Evidenced capabilities are marked _requires live verification_. Automations that use them need the live-actions acknowledgement. |
| The official rules (https://funpay.com/trade/info) could not be accessed from the research environment. | Whether auto-raise, auto-replies and automatic delivery are allowed is **not documented in any text we read**.                                                                                  | All automation is off by default. The user must read the rules and acknowledge the risks.                                        |
| Actions need an **open, logged-in FunPay tab**.                                                         | No 24/7 operation. Nothing runs while the browser is closed or no FunPay tab is open.                                                                                                           | Tasks wait as `awaiting_tab`, and the UI shows _Open funpay.com_.                                                                |
| Raise cooldowns are server-enforced and undocumented.                                                   | FunPro reads the wait time from FunPay's reply. The "every 4 hours" figure is unverified and is not used.                                                                                       | By design.                                                                                                                       |
| FunPay does not show impression or view data to sellers.                                                | Product conversion rates cannot be computed.                                                                                                                                                    | Shown as _unavailable_.                                                                                                          |
| No reorder endpoint.                                                                                    | Listings can only be reordered in FunPro's local view. Reordering on FunPay would need deleting and recreating offers, which FunPro refuses to do automatically.                                | Blocked by platform limitation.                                                                                                  |
| Sellers cannot rate buyers.                                                                             | Buyer feedback is limited to polite chat-message templates.                                                                                                                                     | Blocked by platform limitation.                                                                                                  |
| No server-side sync service exists.                                                                     | Nickname styles that other FunPro users can see (Lite Bot item 52) cannot work.                                                                                                                 | Blocked. Local styling only.                                                                                                     |
| Chat history only covers what FunPro has fetched or seen.                                               | CRM metrics and conversation search are based on locally stored history.                                                                                                                        | Labelled in the UI.                                                                                                              |
| Commission percentages are not published.                                                               | Net prices are _estimates_ unless the commission came from FunPay's own calculator (`/lots/calc`) for that category.                                                                            | Labelled in the UI.                                                                                                              |
| Currency exchange rates                                                                                 | FunPro never converts currencies on its own. A combined view needs a rate the user enters manually, with its source and a timestamp.                                                            | By design.                                                                                                                       |
| Third-party plugin runtime                                                                              | MV3 forbids remote code, and a sandboxed plugin API would need a separate security design. Extension points are internal TypeScript APIs only.                                                  | Not yet implemented.                                                                                                             |
| Multi-account                                                                                           | Would mean handling session cookies, which FunPro refuses to do. Use separate browser profiles instead.                                                                                         | By design.                                                                                                                       |
| Built-in Translator API                                                                                 | Available in recent Chrome only.                                                                                                                                                                | Falls back to the AI provider, or manual entry.                                                                                  |

## Integration checklist

Run this checklist on a **test seller account** before each release. Record the date, the FunPro version and the result. When an item passes, change its capability in `src/adapters/funpay/capabilities.ts` from `evidenced` to `verified` and add a sanitized `live-YYYY-MM-DD-*.html` fixture.

| #   | Capability                                 | Steps                                                                              | Expected                                                                                                     |
| --- | ------------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 1   | Session detection                          | Log in, open any page, open the popup.                                             | _Connected as <name>_. After logout: _Not logged in_.                                                        |
| 2   | Orders parsing                             | Open `/orders/trade`.                                                              | Orders appear in FunPro with the correct status, price, currency and date (Moscow time).                     |
| 3   | Own lots and raise button                  | Open `/lots/<node>/trade`.                                                         | Listings appear and a bump target is discovered (game id).                                                   |
| 4   | Raise                                      | With one bump target, press _Raise now_.                                           | Success message, or a cooldown with a plausible wait time. The next attempt is scheduled after the cooldown. |
| 5   | Raise modal (several sections in one game) | Run item 4 on a game with ≥ 2 sections.                                            | All of the seller's sections are raised.                                                                     |
| 6   | Chat list and history                      | Open `/chat/`, then have a second account send a message.                          | The message appears in FunPro as `customer`. Your own message appears as `self`, FunPay notices as `system`. |
| 7   | Send message                               | Send a manual message from FunPro to the test buyer.                               | It is delivered exactly once.                                                                                |
| 8   | Flood handling                             | Send several messages quickly.                                                     | FunPay's flood error pauses sending. Nothing is duplicated.                                                  |
| 9   | Offer edit                                 | Bulk-change the price of **one** test offer, then restore it from the backup.      | The price changes on FunPay, and the restore works.                                                          |
| 10  | Offer delete                               | Delete one throwaway offer through bulk delete (typed confirmation).               | Only that offer is deleted.                                                                                  |
| 11  | Clone                                      | Clone a test offer.                                                                | The new offer has the same fields and is created inactive, or as configured.                                 |
| 12  | Commission calc                            | Run _Detect commission_ for a node.                                                | The percentage roughly matches FunPay's buyer price table.                                                   |
| 13  | Review reply                               | Reply to a test review.                                                            | The reply appears on FunPay.                                                                                 |
| 14  | Finance                                    | Open `/account/balance`.                                                           | Operations appear with the correct sign and kind.                                                            |
| 15  | Competitors                                | Open a public `/lots/<node>/` page.                                                | Competitor offers are stored. Your own offer is excluded from recommendations.                               |
| 16  | Auto-reply end to end                      | Enable auto-replies with _approval required_, then message from the buyer account. | A draft appears. Approving it sends exactly one message.                                                     |
| 17  | Post-order message                         | Confirm a test order from the buyer account.                                       | One post-order message, and none for historical orders.                                                      |
| 18  | Delivery                                   | Reserve an inventory item for a paid test order.                                   | A delivery draft is created with the item, and the item is never reused.                                     |
| 19  | Emergency stop                             | With automations running, press _Emergency stop_.                                  | No further automated requests. The queue is cancelled.                                                       |
| 20  | Firefox                                    | Repeat items 1, 2, 4 and 7 in Firefox ≥ 128.                                       | Same results. Sounds play without the offscreen document.                                                    |
| 21  | Telegram                                   | Connect a bot, send a test, run `/status`, then `/stop CONFIRM`.                   | Only the authorised chat is accepted, and `/stop` triggers the emergency stop.                               |
| 22  | AI                                         | Configure a provider and draft a reply.                                            | Consent is required, redaction is applied, and the result is an editable draft.                              |
