# Feature implementation matrix

Status legend (as required by the project brief):

| Mark | Status                                          | Meaning                                                                                                                                                                                                                                                               |
| ---- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ✅   | **Implemented and tested**                      | Logic and UI exist and are covered by automated tests: unit/integration tests with fake IndexedDB and fixtures, and/or Playwright tests on the built extension.                                                                                                       |
| 🟡   | **Implemented but requires live verification**  | The feature sends requests to FunPay or depends on FunPay page markup that FunPro maintainers have not yet verified on the live site. It is tested against sanitized fixtures and mocks. See the [integration checklist](KNOWN-LIMITATIONS.md#integration-checklist). |
| ⛔   | **Blocked by a documented platform limitation** | It cannot be built honestly with what FunPay or the browser offers.                                                                                                                                                                                                   |
| ❌   | **Not yet implemented**                         |                                                                                                                                                                                                                                                                       |

Every feature that consumes FunPay data depends on the adapter rows in **section 0**, and all of those still need live verification. A ✅ on a downstream feature means its own logic is verified given correctly parsed data.

Test paths are relative to `tests/unit/` unless they start with `e2e/`.
